# Security Policy

Quartz Drive takes security very seriously. As an End-to-End Encrypted (E2EE), Zero-Knowledge cloud storage platform, the architecture is designed to protect user data even in the event of a total infrastructure compromise.

## Reporting a Vulnerability

If you believe you've found a security issue in Quartz Drive, please **DO NOT** open a public GitHub issue.
We encourage you instead to notify us privately by email instead: **[security@quartzapp.top](mailto:security@quartzapp.top)**

We will endeavor to respond to your report within 48 hours. Please include:
- A detailed description of the vulnerability.
- Steps to reproduce the issue.
- Potential impact and any suggested mitigations.

### Responsible Disclosure
We ask that you:
- Give us a reasonable amount of time to correct the issue before making it public.
- Avoid violating the privacy of others, disrupting our systems, destroying data, or harming the user experience.
- Perform testing only on accounts you own or have explicit permission to test (e.g., local deployments).

## Supported Versions

For frontend, only the latest commit on the `master` branch is supported for security updates.

For backend, only the `latest release` is supported for security updates.

| Version                   | Supported          |
|---------------------------| ------------------ |
| Frontend: `master`        | :white_check_mark: |
| Backend: `latest release` | :white_check_mark: |
| Older                     | :x:                |

## Bug Bounty

We do not have a formal bug bounty program or financial rewards at this time. However, we deeply appreciate responsible disclosures and will gladly offer public acknowledgment/kudos for valid, high-impact vulnerability reports.

In the future we may consider giving out free storage to those who greatly contributed to the security of this project.
